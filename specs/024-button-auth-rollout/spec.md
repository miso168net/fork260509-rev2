# Feature Specification: ButtonAuth Rollout（角色頁/選單頁寫按鈕納入「按鈕權限」可指派 + 即時生效）

**Feature Branch**: `024-button-auth-rollout`

**Created**: 2026-06-04

**Status**: Draft

**Input**: User description: "把 022 用戶頁的『按鈕權限可編輯迴路』（在角色管理頁「按鈕權限」介面勾選 → 自動同步授權 → 頁面按鈕依授權顯/隱）rollout 到角色頁與選單頁，讓角色/選單頁的寫操作按鈕也成為可經編輯介面獨立指派、即時生效的按鈕權限。設計來源:[`docs/superpowers/024-button-auth-rollout.md`](../../docs/superpowers/024-button-auth-rollout.md)（Phase 0 brainstorm,K1–K4 親決）。承 [§2.26 follow-up]、鏡像 022-manage-button-auth。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 維運者為角色指派「角色管理頁」可見寫按鈕,即時生效 (Priority: P1)

身為系統維運者(最高權限),我希望在角色管理頁的既有「按鈕權限」編輯介面中,為某個角色勾選/指派其在**角色管理頁**可見的寫操作按鈕(新增/編輯/刪除),儲存後**即時生效**(無需重啟):被授予的角色其人員在角色管理頁看得到對應按鈕、未授予的看不到。

**Why this priority**: 這是把「按鈕權限可編輯迴路」(022 僅覆蓋用戶頁)擴及角色頁的核心一步,單獨交付即構成價值(維運者首次能控制角色頁寫按鈕對各角色的可見性、即時生效)。是 MVP。

**Independent Test**: 以最高權限身分開啟某角色的「按鈕權限」編輯介面 → 介面**列出角色管理頁的寫按鈕**為可勾選項 → 勾選其一(如「編輯」)提交 → 以該角色人員身分檢視角色管理頁,該按鈕出現;移除後即時消失。期間其他角色不受影響。

**Acceptance Scenarios**:

1. **Given** 角色管理頁的寫按鈕(新增/編輯/刪除)與某一角色, **When** 維運者於「按鈕權限」介面勾選其中數顆並儲存, **Then** 該角色授權更新,該角色人員即時(無需重啟)於角色管理頁看得到被授予的按鈕、看不到未授予的。
2. **Given** 某角色已被授予角色頁「編輯」按鈕, **When** 維運者於介面取消勾選並儲存, **Then** 該角色人員的角色管理頁即時不再顯示「編輯」按鈕。
3. **Given** 維運者開啟某角色的「按鈕權限」介面, **When** 載入, **Then** 該角色目前已授予的角色頁按鈕以勾選狀態正確預載。

### User Story 2 - 維運者為角色指派「選單管理頁」可見寫按鈕,即時生效 (Priority: P2)

身為系統維運者,我希望以同一範式,在「按鈕權限」編輯介面為角色指派其在**選單管理頁**可見的寫操作按鈕(新增/加子選單/編輯/刪除),儲存後即時生效。

**Why this priority**: 與 US1 同範式、擴及選單頁;服務於同一能力但次要(可在 US1 之後獨立交付與驗證)。

**Independent Test**: 以最高權限身分為某角色於「按鈕權限」介面勾選選單管理頁的寫按鈕 → 該角色人員於選單管理頁看得到對應按鈕;未授予者看不到;「加子選單」僅在可加子的選單列上、且須獲授予才顯示。

**Acceptance Scenarios**:

1. **Given** 選單管理頁的寫按鈕(新增/加子選單/編輯/刪除)與某角色, **When** 維運者於「按鈕權限」介面勾選並儲存, **Then** 該角色人員即時於選單管理頁看得到被授予的按鈕。
2. **Given** 某角色未被授予選單頁任何寫按鈕, **When** 該角色人員檢視選單管理頁, **Then** 不顯示任何寫按鈕(僅可讀)。
3. **Given** 「加子選單」按鈕(僅適用於可含子項的選單列), **When** 角色未獲授予該按鈕, **Then** 即使在可加子的選單列上也不顯示。

### User Story 3 - 三個管理頁按鈕顯示隨授權變動即時反映 + 既有不破 (Priority: P3)

身為系統維運者,我希望用戶/角色/選單三個管理頁的寫按鈕顯示,都能**隨登入者的按鈕授權變動即時反映**(無陳舊顯示),且既有用戶頁的按鈕權限行為不因本波被破壞。

**Why this priority**: 一致性與正確性保障(補齊既有用戶頁按鈕顯示在頁內授權變動時未即時重繪的缺口、並確保三頁行為一致);屬安全網,優先序最低但必要。

**Independent Test**: 在三個管理頁分別驗證:登入者按鈕授權集變動後,頁面寫按鈕的顯示/隱藏即時跟著變(非停留舊狀態);用戶頁既有按鈕權限(022)行為逐項維持。

**Acceptance Scenarios**:

1. **Given** 某登入者在某管理頁, **When** 其按鈕授權集發生變動, **Then** 該頁寫按鈕的顯示/隱藏即時反映新授權(無陳舊狀態)。
2. **Given** 既有用戶管理頁的按鈕權限行為, **When** 本波交付後, **Then** 用戶頁按鈕顯示/隱藏與既有一致(回歸不破)。

### Edge Cases

- **按鈕可見性與實際可執行性為兩獨立維度(本波刻意)**:某角色被授予某寫按鈕(看得到),但該角色不具對應寫操作的底層權限 → 按鈕仍顯示、點擊執行時由既有授權把關拒絕(權限不足)。本波**不**自動對齊兩者(見 FR-008)。
- **最高權限角色(超管)**:預設恆可見角色/選單頁全部寫按鈕(開箱即用)。
- **未獲授予的角色**:對應寫按鈕不顯示(僅可讀)。
- **即時 + 跨實例**:指派變更後不重啟即反映;多服務實例時所有實例即時一致。
- **可逆**:本波對按鈕清單與初始授權的資料變更 MUST 可完整還原,且不影響既有用戶頁/選單可見性授權。
- **「加子選單」的資料前提**:該按鈕本就僅適用於可含子項的選單列;授權 gating 疊加於此資料前提之上(兩者皆滿足才顯示)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓維運者經**既有的「按鈕權限」編輯介面**(角色管理頁內),為某角色指派其在**角色管理頁**與**選單管理頁**可見的寫操作按鈕(新增/編輯/刪除/加子選單),與既有用戶頁同一操作範式。
- **FR-002**: 指派變更 MUST **即時生效**(無需重啟)且 MUST 在所有服務實例即時一致 —— 沿用既有按鈕權限同步機制。
- **FR-003**: 角色管理頁與選單管理頁 MUST 依登入者角色的按鈕授權,**顯示/隱藏**對應寫按鈕(獲授予才顯示),與既有用戶頁 gating 範式一致。
- **FR-004**: 系統 MUST 維護一份涵蓋角色/選單管理頁寫操作的**可指派按鈕清單**,作為編輯介面與頁面 gating 的單一來源;清單 MUST 可被既有「按鈕權限」編輯介面列出與勾選。
- **FR-005**: 最高權限角色(超級管理員)MUST **預設可見/可用**角色與選單管理頁的全部寫按鈕(開箱即用);其餘角色 MUST **預設不獲授予**、由維運者經編輯介面指派。
- **FR-006**: 寫按鈕的顯示/隱藏 MUST 隨登入者按鈕授權變動**即時反映於頁面**(無陳舊顯示);此即時反映 MUST 涵蓋用戶/角色/選單三個管理頁(含修正既有用戶頁同類行為)。
- **FR-007**: 既有能力 MUST NOT 因本波被破壞(回歸):既有用戶管理頁按鈕權限行為、選單/角色/用戶讀寫端、選單可見性與按鈕權限編輯、既有授權階梯 MUST 維持原行為。
- **FR-008**: 本波 MUST NOT 包含:「按鈕可見性自動對齊底層可執行權限」(自動 visible=clickable 推導)、不同部署的模式總開關、或讀取使用者可呼叫端點集的機制 —— 皆留後續 feature。按鈕權限維持**可獨立指派**的維度(刻意,見 Edge Cases)。

### Key Entities *(include if data involved)*

- **按鈕權限(Button permission)**:角色 × 管理頁寫操作按鈕的**可見性授權**(承既有機制)。本波擴及角色/選單管理頁的寫按鈕;變更為即時生效、跨實例一致;不新增資料表、不改授權機制本身。
- **可指派按鈕清單(Button registry)**:各管理頁可用寫操作按鈕的集合(以按鈕識別為鍵),作為編輯介面與 gating 的單一來源;本波新增角色/選單管理頁的寫按鈕項。
- **角色(Role)**:最高權限角色預設可見全部寫按鈕;其餘角色預設無、由維運者指派。承既有角色資料。

## Success Criteria *(mandatory)*

> 下列百分比指對所列舉的代表性 case 矩陣**全數通過**(各類正反例至少各一),非統計抽樣。

### Measurable Outcomes

- **SC-001**: 維運者可經「按鈕權限」編輯介面為角色指派角色/選單管理頁的寫按鈕,變更 100% **即時反映**(獲授予者該頁可見、未授予者不可見)於該角色人員,**無需重啟**。
- **SC-002**: 指派變更在**所有服務實例 100% 即時一致**生效。
- **SC-003**: 最高權限角色 100% **預設可見**角色與選單管理頁全部寫按鈕;其餘角色預設 0 顆(未指派前)。
- **SC-004**: 用戶/角色/選單三個管理頁的寫按鈕顯示 100% **隨授權變動即時反映**(0 處陳舊顯示)。
- **SC-005**: 回歸:既有用戶管理頁按鈕權限、選單/角色/用戶讀寫端、選單可見性/按鈕權限編輯、授權階梯 100% 維持原行為。
- **SC-006**: 本波對資料的變更 100% 可逆還原,且 0 影響既有用戶頁按鈕授權與選單可見性授權。

## Assumptions

- **沿用既有「按鈕權限」編輯介面與同步機制**(022 落地):本波只把角色/選單管理頁的寫按鈕**納入**該既有迴路(可指派、即時同步、頁面 gating),**不改機制、不新增編輯介面元件、不新增資料表**。
- **按鈕可見性為可獨立指派的維度**:不自動綁定底層可執行權限(decoupled,本波刻意;對齊兩者留後續 feature)。
- **全站管理頁限用戶/角色/選單三頁**:本波涵蓋角色 + 選單兩頁(用戶頁 022 已做),三頁的即時反映一致性一併處理。
- **最高權限角色恆為全可見的預設**:其餘角色初始不獲授予,授權純由維運者於編輯介面決定。
- **wire 形狀與前端送出形**沿既有按鈕權限契約(同 022);本波不在 spec 固定按鈕識別字串的確切命名(規劃/研究階段以實際 code 對齊)。
