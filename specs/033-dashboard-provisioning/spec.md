# Feature Specification: Observability — Dashboard Provisioning

**Feature Branch**: `033-dashboard-provisioning`

**Created**: 2026-06-08

**Status**: Draft

**Input**: User description: "@docs/superpowers/033-dashboard-provisioning.md" — Phase 6 觀察性第三刀：**儀表板（dashboards）provisioning**。接續 031 obs-min（log）+ 032 obs-full（metrics），把觀察性從「逐次手打查詢（Explore）+ 告警」補成「開觀察 UI 即見的現成監控面板」。涵蓋：後端應用面板、基礎設施（資料庫/快取）面板、全域總覽面板、維運 job 面板、log pipeline 面板。隨部署可重現 provision、opt-in 維運堆疊、零侵入應用行為。儀表板告警通知管道（送信）/ 對外暴露硬化明確排除為後續。設計來源見 brainstorm spec-design（8 決策已拍板）。

> **術語**：本 spec「**監控面板 / 面板**」= 一張**儀表板（dashboard）**——一組相關圖表的集合（如「後端應用面板」「資料庫面板」）;「**圖表（panel）**」= 一張儀表板內的單一視覺化（綁一條查詢）。下文 ≥6「面板」皆指儀表板。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 維運者開觀察入口即見後端應用監控面板（Priority: P1）🎯 MVP

身為維護此部署的維運者（人類或自動化），當我要看後端應用是否健康時，我希望**開啟觀察入口就直接看到一張現成的「後端應用」監控面板**（請求量、延遲分位、錯誤率、授權放行/拒絕計量），而不必每次自己手打查詢語句重建這些圖。

**Why this priority**: 後端應用的請求/延遲/錯誤/授權是第一線健康指標；把它做成「一打開就看得到」的面板，是觀察性從「能查」進化到「現成可看」最大的單點價值。即使只有這一張面板，也已能回答「app 健不健康」→ 可獨立交付的 MVP。

**Independent Test**: 啟用觀察堆疊後開觀察 UI → 在面板清單看到「後端應用」面板 → 開啟後其圖表立即顯示真實的請求率/延遲/錯誤/授權資料（非空、非「資料來源找不到」），全程不需手打任何查詢。

**Acceptance Scenarios**:

1. **Given** 觀察堆疊已啟用且應用有流量，**When** 維運者開觀察入口的面板清單，**Then** 看到一張現成的「後端應用」面板。
2. **Given** 同上，**When** 維運者開啟該面板，**Then** 圖表立即顯示依路由/狀態分群的請求率、延遲分位、錯誤率、以及授權放行/拒絕計量，皆為真實資料。

---

### User Story 2 - 維運者見現成的基礎設施（資料庫/快取）監控面板（Priority: P2）

身為維運者，當我懷疑問題出在資料庫或快取時，我希望**開觀察入口就有現成的「資料庫」與「快取」深度監控面板**（連線、容量、效能、命中率等），不必自己拼湊這些圖。

**Why this priority**: 後端應用指標常需對照基礎設施狀態定位根因；現成的 infra 面板讓「DB 慢還是 app 慢」一眼可判。建立在 US1 的觀察入口之上、可獨立驗。

**Independent Test**: 啟用觀察堆疊 → 面板清單看到「資料庫」「快取」兩張面板 → 開啟後圖表顯示真實的連線/容量/效能/命中率等深度狀態。

**Acceptance Scenarios**:

1. **Given** 觀察堆疊已啟用，**When** 維運者開「資料庫」面板，**Then** 看到連線數、容量、交易率、快取命中等深度狀態圖。
2. **Given** 觀察堆疊已啟用，**When** 維運者開「快取」面板，**Then** 看到記憶體用量、用戶端、命中率、指令率等深度狀態圖。

---

### User Story 3 - 維運者見全域總覽面板與維運 job 面板（Priority: P2）

身為維運者，我希望有一張**「全域總覽」面板**讓我一眼看全 stack 健康（各採集目標是否存活、關鍵率），以及一張**「維運 job」面板**讓我確認週期性清理 job 是否正常跑（上次成功時間、距今多久、處理筆數）。

**Why this priority**: 總覽面板是維運的第一落點（先看全貌再鑽細節）；維運 job 面板確保「清理有跑、多久沒跑、清了多少」可查證（短命 job 結束後仍可見）。建立在 US1/US2 的資料之上、可獨立驗。

**Independent Test**: 啟用觀察堆疊 → 面板清單看到「全域總覽」與「維運 job」面板 → 總覽顯示各採集目標存活狀態 + 關鍵率；維運 job 面板顯示上次成功時間 + 距今 age + 處理筆數。

**Acceptance Scenarios**:

1. **Given** 觀察堆疊已啟用，**When** 維運者開「全域總覽」面板，**Then** 看到各採集目標（應用/資料庫/快取/job 推送入口）的存活狀態與關鍵率。
2. **Given** 一次維運 job 跑完後，**When** 維運者開「維運 job」面板，**Then** 看到該 job 的上次成功時間、距今多久、上次處理筆數（即使 job 已退出）。

---

### User Story 4 - 維運者見現成的 log pipeline 面板（Priority: P3）

身為維運者，我希望有一張**現成的「log pipeline」面板**，顯示各服務的 log 量、錯誤/警告率、與對外存取狀態，讓我不必每次手打 log 查詢就能看出哪個服務在噴錯。

**Why this priority**: log 觀察（031）目前是 Explore-only；把「各服務 log 量/錯誤率」做成現成面板，補完 log 半邊的「可看」面。建立在 031 log 資料之上、可獨立驗。

**Independent Test**: 啟用觀察堆疊（含 log 半邊）→ 面板清單看到「log pipeline」面板 → 開啟後顯示各服務 log 量、錯誤/警告率、對外存取狀態碼分佈，皆真實資料。

**Acceptance Scenarios**:

1. **Given** 觀察堆疊（含 log）已啟用且有流量，**When** 維運者開「log pipeline」面板，**Then** 看到依服務分群的 log 量與錯誤/警告率。
2. **Given** 同上，**When** 維運者看對外存取面板，**Then** 看到存取請求率與狀態碼分佈。

---

### User Story 5 - 面板隨部署可重現就緒、opt-in、零侵入（Priority: P3）

身為維運者，我需要這些面板是**隨部署自動就緒**（不必每次手動在 UI 重建）、**opt-in**（隨觀察堆疊啟用才有、不隨一般服務啟動）、且啟用與否都**不改變**應用對最終使用者的任何可觀察行為（純觀察面、不新增採集或埋點）。

**Why this priority**: 可重現 provision 是維運可信度基礎；opt-in + 零侵入與 031/032 的紀律一致——面板是輔助維運能力、非業務功能。

**Independent Test**: 全新部署啟用觀察堆疊 → 面板**自動**出現（非手建）；以一般方式啟動應用服務（未啟用觀察堆疊）→ 面板組**未**出現；比對啟用前後應用對外行為（回應碼/形狀）**完全相同**。

**Acceptance Scenarios**:

1. **Given** 一份全新部署，**When** 啟用觀察堆疊，**Then** 所有面板**自動** provision 就緒（清單非空、無「資料來源找不到」、provisioning 無錯）。
2. **Given** 一份部署，**When** 以一般方式啟動應用服務（未啟用觀察堆疊），**Then** 面板組**不**隨之出現。
3. **Given** 面板組已啟用，**When** 比對啟用前後同一組應用請求的回應，**Then** 回應碼與回應形狀 0 變化（純觀察、零侵入）。

---

### Edge Cases

- **某資料來源所屬堆疊未啟動**（如只啟 metrics 未啟 log）：依賴該來源的面板顯示無資料/來源不可達，但**不**讓 provisioning 報錯、不影響其他面板。
- **採集元件的指標命名與面板查詢不一致**：面板顯空集；驗收時須對齊面板查詢與**實際**指標/標籤命名（不信抽象假設）。
- **面板以不穩定識別引用資料來源**：換環境/重 provision 時引用斷裂、面板顯「資料來源找不到」→ 面板引用資料來源 MUST 用穩定識別。
- **基礎設施指標量龐大**（數百個）：面板只取關鍵子集呈現，不全量塞、不爆載入。
- **短命維運 job 已退出**：其上次執行推送的狀態仍可在面板顯示（不因 job 容器消失而遺失）。
- **觀察查詢入口暫不可達**：屬輔助維運面、不得影響應用請求（與 031/032 旁路紀律一致）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供一張現成的**後端應用監控面板**，涵蓋請求量、延遲分位、錯誤率、與授權決策（放行/拒絕）計量，維運者開觀察入口即見、不需手打查詢。
- **FR-002**: 系統 MUST 提供現成的**基礎設施監控面板**（資料庫、快取各一），呈現其連線/容量/效能/命中率等深度狀態。
- **FR-003**: 系統 MUST 提供一張現成的**全域總覽面板**（各採集目標存活狀態 + 關鍵率）。
- **FR-004**: 系統 MUST 提供一張現成的**維運 job 面板**（上次成功時間、距今 staleness、處理筆數；短命 job 退出後仍可見）。
- **FR-005**: 系統 MUST 提供一張現成的 **log pipeline 面板**（各服務 log 量、錯誤/警告率、對外存取狀態）。
- **FR-006**: 所有面板 MUST **隨部署可重現地 provision**（隨觀察堆疊起即就緒、不依賴手動 UI 建立）。
- **FR-007**: 面板對其資料來源（指標/log）的引用 MUST 用**穩定識別**，使換環境/重 provision 不致引用斷裂（不得「資料來源找不到」）。
- **FR-008**: 此面板組 MUST 為 **opt-in 維運元件**：僅隨觀察堆疊被明確啟用時出現、不隨一般應用服務啟動。
- **FR-009**: 啟用此面板組 MUST NOT 改變任何**應用對外可觀察行為**（回應碼/回應形狀/業務邏輯/wire 契約零變）；面板為唯讀觀察面、**不新增任何採集或埋點**。
- **FR-010**: 此面板組 MUST 能在**正式部署產物**中運行；且觀察查詢入口在正式部署中 MUST NOT **對外暴露**（沿既有 internal-only）。

### Key Entities *(include if feature involves data)*

- **監控面板（dashboard）**：一組預先定義、針對特定主題（應用/基礎設施/總覽/job/log）的圖表集合；隨部署 provision，維運者開觀察入口即見。
- **圖表（panel）**：面板內單一視覺化，綁定一條查詢 + 一個資料來源；呈現某指標/log 維度。
- **資料來源引用（datasource reference）**：面板查詢指向的指標/log 來源；MUST 用穩定識別（避免換環境斷裂）。
- **維運 job 狀態（job run metric）**：短命維運 job 推送的上次成功時間/處理筆數；job 退出後仍可被面板呈現。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 維運者開觀察入口即見 **≥6 張現成面板**（後端應用 / 資料庫 / 快取 / 全域總覽 / 維運 job / log pipeline），**不需**手打任何查詢即可看圖。
- **SC-002**: 每張面板的代表圖表載入即顯**真實資料**（無「資料來源找不到」錯誤、非空集）。
- **SC-003**: 面板隨部署**自動就緒**（全新部署啟用觀察堆疊後開 UI 即見，非手動建立）；provisioning 無載入錯誤。
- **SC-004**: 一般啟動（未啟用觀察堆疊）時面板組 **100% 不出現**；啟用前後應用對外行為（回應碼/回應形狀）**0 變化**。
- **SC-005**: 面板組在**正式部署產物**中可運行（經正式產物啟動驗證）；觀察查詢入口在正式部署中**不對外暴露**。

## Assumptions

- 面板**複用既有觀察 UI**（031/032 已建的維運 UI）+ 既有指標（032 metrics）/ log（031）資料源；**不改前端應用、不新增任何採集或埋點**（面板為唯讀觀察視圖）。
- 範圍**僅限面板 provisioning**；告警規則已於 032 交付，**告警通知管道（送信）明確排除**為後續。
- opt-in：面板隨觀察堆疊（log / metrics）啟用才出現；一般部署不含。**完整面板需對應資料源堆疊在跑**（log 面板需 log 半邊、指標面板需 metrics 半邊）。
- 基礎設施面板採用其**採集元件專案提供的標準面板**（upstream 產物、隨採集元件版本對齊指標命名）；應用/總覽/維運 job/log 面板自製。
- prod 面板查詢入口 **internal-only**（沿 031/032）；「對外暴露（反向代理 + TLS + 採集端認證硬化）」留後續 security pass。
- 後端應用**已有指標與 log 採集**（031/032），本面板只「呈現」現有資料、不新增資料源。
